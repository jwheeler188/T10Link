T10Link manual

T10Link brings Honeywell Home T9 / T10 / T10 Pro thermostats into Savant locally. It uses the Apple HomeKit protocol on your own network, so it doesn't need the Honeywell/Resideo cloud or a Resideo account, and it keeps working when the internet is down.

The T10Link bridge is a small service that runs on the Savant host Mac itself, another Mac, a Raspberry Pi or any Linux box that's always on. It is paired with each thermostat over HomeKit, and it talks to the Savant host over a plain TCP connection on port 2400. One bridge and one Blueprint component handle up to 8 thermostats (16 with a regenerated profile).

What works

Verified on a T10 Pro, firmware 1.5.3, with one RedLINK room sensor:

FeatureOver HomeKit
Mode: Off / Heat / Cool / Autoread and set
Heat and cool setpointsread and set (see the note below)
Current temperature, humidityread, pushed instantly
Heating / cooling / idleread
RedLINK room sensors: temperature, humidity, motion, low batteryread
Occupancy (thermostat's own sensor)read
Filter 1 / 2 change remindersread and reset
Fan mode (Auto / On / Circulate)not available
Hold / schedule overridenot available

Setpoints and mode. Over HomeKit the T10 only takes the setpoint of the mode it's in: the heat setpoint in Heat, the cool setpoint in Cool, both in Auto. A setpoint for another mode (for example the heat setpoint from Savant's scheduler while it's cooling) is saved by the bridge and written as soon as the thermostat switches to that mode, whether the switch comes from Savant, the wall or the Honeywell app. Until then Savant shows the saved value, and T_SAVED_SETPOINTS lists what's waiting.

Every change is confirmed: the Savant app only shows a new setpoint or mode once the thermostat reports it back. Until then T_PENDING says what is being changed, and if the thermostat doesn't confirm within 20 seconds, T_ERROR says so.

Requirements

  • A Honeywell Home T9 or T10 (Pro / +) on Wi-Fi, not already paired with Apple Home. HomeKit allows one controller to do the first pairing. (Apple Home can't be added on top of T10Link through the thermostat's screen.)
  • A machine for the bridge that's always on, on the same network as the thermostat, with Python 3.10 or newer:
    • Mac (the Savant host, or any other): macOS 11 or newer, Intel or Apple silicon. Apple's built-in python3 is 3.9, so if there's no newer Python the installer offers to install Python 3.13 from python.org for you (see Install the bridge).
    • Raspberry Pi: Raspberry Pi OS Bookworm or newer, 32- or 64-bit (Python 3.11+ is built in). Any Pi from the 3B up is plenty. Other Linux: Debian 12+, Ubuntu 22.04+, with systemd.
  • Internet access once, while installing, to download the HomeKit library (aiohomekit). After that everything stays on your network.
  • A DHCP reservation for each thermostat on your router (also called a static lease or fixed IP). The bridge connects by IP address, so if the router gives the thermostat a new address, Savant loses it. The web page's search shows each thermostat's IP and MAC address to reserve.
  • Savant Pro host. The profile works with any Savant version that has the HVAC service.

Install the bridge

One command, on the machine that will run the bridge (Terminal on a Mac; a Pi over ssh):

curl -fsSL https://raw.githubusercontent.com/jwheeler188/T10Link/main/get.sh | bash

It downloads the latest release from GitHub, checks its SHA-256, and runs the installer, which asks for your password (sudo) when it needs it. On a Savant host, run it as the RPM user (it then runs the service as RPM), or add -s -- --user RPM:

curl -fsSL https://raw.githubusercontent.com/jwheeler188/T10Link/main/get.sh | bash -s -- --user RPM

Or from the zip: download T10Link-<version>.zip from the GitHub release, unzip it and run ./install.sh in the T10Link folder (same options).

Re-running either one upgrades in place and keeps config.json, the pairing, sensor numbering and saved setpoints.

What it does:

  • Mac: puts the bridge in ~/T10Link with its own Python environment, installs a launchd service (org.t10link.bridge, started now and at every boot), links the t10link command into /usr/local/bin, allows Python through the macOS firewall if the firewall is on, and opens the web page if you're sitting at the Mac. If there's no Python 3.10 or newer, it offers to install Python 3.13 from python.org (--install-python says yes in advance). That download is checked against a known SHA-256 and the Python Software Foundation's signature, and it's installed framework only: no python3 command in /usr/local/bin, no PATH or shell profile changes, no apps. So on a Savant host, Savant's own scripts (which run whatever python3 they find) keep using the one they use now.
  • Raspberry Pi / Linux: puts the bridge in /opt/t10link with its own Python environment (aiohomekit takes a few minutes on a Pi), installs the t10link-bridge systemd service and the t10link command, and installs python3-venv with apt if it's missing. The service runs as the user who ran the installer.

The installer finishes by printing the web page address, http://<bridge IP>:2401. Everything else is done there: see Pair the thermostat.

If the bridge isn't on the Savant host, it refuses Savant's first connection (only allowed machines may control the thermostats). The web page then shows "Savant at ... was refused" with an Allow button, which adds that address to allowed_clients.

Pair the thermostat

On the web page, http://<bridge IP>:2401, from any computer or phone on your network:

  1. Reserve the thermostat's IP in your router first (a DHCP reservation for its MAC address). Search the network lists every T9 / T10 it finds with its IP and MAC, so you can copy them into the router.
  2. Press Use next to the thermostat, give it a name if you like ("Living Room"), tick This IP is reserved in the router and press Add thermostat. It gets the next number, which is its ThermostatAddress in Blueprint. (You can also type an IP: Menu > Wi-Fi on the thermostat shows it.)
  3. On the thermostat open Menu > Connect HomeKit. It shows an 8-digit code (123-45-678). The code changes each time that screen opens, so use the one showing now.
  4. Type it in the thermostat's card and press Pair. The thermostat's Wi-Fi sleeps a lot, so allow up to a minute. The card then shows the temperature and mode.

A thermostat that's in Apple Home (or another HomeKit app) can't be paired until it's removed there; the search shows it as "Paired to another HomeKit app".

Only HomeKit's long-term pairing keys are saved (pairing.json in the install folder, and pairing-2.json, pairing-3.json ... for the other thermostats; readable by the service user only). The setup code is never stored. The Honeywell Home / Resideo app keeps working alongside.

On the command line instead: add the thermostat to config.json, then t10link pair (it pairs the next unpaired thermostat; t10link pair 2 pairs thermostat 2).

The web page

http://<bridge IP>:2401 (the installer prints it). It shows:

  • each thermostat: number, name, IP, connected or not, temperature, mode, setpoints, humidity and room sensors, and a Pair box while it isn't paired
  • Rename: the name shown on the page and in Savant (T_NAME), saved in config.json. A T10 reports "T10 Thermostat" over HomeKit whatever the Honeywell Home app calls it, and HomeKit doesn't let anyone change that, so T10Link keeps its own name. Blank goes back to the HomeKit name (still in T_HOMEKIT_NAME).
  • Service (on each thermostat):
    • Change IP: the same thermostat has a new address. The pairing is kept and the bridge reconnects at once. The search also spots a paired thermostat that moved ("Thermostat 2 moved here") and offers this in one click.
    • Unpair: the thermostat forgets the bridge and can be paired again, here or with Apple Home. It stays in the list with its number.
    • Remove: unpairs it (if paired) and takes it out of the list. Thermostats after it move up one number (3 becomes 2 ...), and the page reminds you to change their ThermostatAddress in Blueprint to match.
    • If the thermostat doesn't answer when unpairing or removing, nothing changes, and the page offers to delete the bridge's keys anyway. The thermostat then still lists the bridge, so do Menu > Advanced Setup > Reset > HomeKit Reset on it before pairing it again.
    • Its MAC address, for the router's DHCP reservation.
  • Add a thermostat: the DHCP reservation reminder, Search the network, and the add form.
  • Savant setup: the Device IP Address and port for Blueprint, whether Savant is connected, and a Download the Blueprint profile link (the import folder, zipped).
  • A notice with an Allow button when a Savant host was refused.

Replacing a thermostat: Unpair the old one (or Remove, then Add), Change IP if the new one has a different address, and pair the new one. Its number, and so the Savant data table row, stays the same.

Who can open it: machines on your private network (web_clients), plus the machines in allowed_clients. Anyone who can open it can also unpair or remove thermostats, so set web_password in config.json if others share your network. The page uses plain HTTP on your network, like the Savant connection; the setup code is only used once and never stored. To turn the page off, set web_port to 0.

Several thermostats

One bridge handles all the thermostats in the house, and Blueprint needs one T10Link component for it. Each thermostat is one row in the HVAC data table. Don't add a second T10Link component for the same bridge, and don't import the profile again.

  1. Add and pair each one on the web page, in the order you want to number them. The first is thermostat 1, the second thermostat 2, and so on; new ones go at the end. The number ties each data table row to its thermostat, so if you remove one from the middle, the ones after it move up and their ThermostatAddress in Blueprint must change to match. (By hand: list them under thermostats in config.json, then t10link restart and t10link pair for each.)
  2. In Blueprint's HVAC data table add one row per thermostat on the same T10Link component, with ThermostatAddress [1] = its number: 1, 2, 3 ... Each row gets its own Zone, and its own Heat / Cool / Auto ticks.
RowControllerThermostatAddress [1]
Living RoomT10Link1
Primary BedroomT10Link2
UpstairsT10Link3

State names. Thermostat 1 keeps the names in Appendix A. Thermostat n has the same states with:

  • Savant's address suffix: ThermostatMode_2, ThermostatCurrentTemperature_2, IsCurrentHVACModeHeat_2
  • Tn_ instead of T_: T2_MODE, T2_TEMP, T2_ONLINE, T2_ERROR
  • Tn_ in front of the room sensors: T2_SENSOR1_TEMP, T2_SENSOR1_MOTION

The SYS_ states cover the whole bridge: SYS_ONLINE = 1 only when every thermostat is connected, and SYS_ERROR names the thermostat, e.g. "thermostat 2: thermostat unreachable". Gate an automation for one thermostat on its own T_ONLINE / T2_ONLINE.

Custom actions take a Thermostat argument (1, 2, 3 ...; blank = 1).

The shipped profile has states for 8 thermostats. For more (up to 16), regenerate it: python3 profile/generate_profile.py --thermostats 12, then re-import it.

Several thermostats were tested with simulated thermostats (built from a real T10's HomeKit data), and a single T10 Pro on real hardware.

Using it in Savant

  • Climate screen: mode, setpoints and temperature work from the Savant app's built-in HVAC screen.
  • Schedules: HomeKit can't read or change the thermostat's own schedule, so run the schedule in Savant:
    1. At the thermostat, turn its schedule off (Menu > Schedule; switch the schedule off). Otherwise it changes the setpoints at its own program times, and Savant's changes only last until the next period.
    2. In the Savant app, set up the climate schedule for the zone. At each period Savant sends the heat and cool setpoints; the bridge writes the one the current mode uses and saves the other (see the setpoint note under What works).
    3. Check once: after a scheduled change, the thermostat's screen should show the new setpoint with no "Hold" message.
  • Triggers and workflows: use the T_* and SENSORn_* states (thermostat 2: T2_*, T2_SENSORn_*). Gate automations on SYS_ONLINE = 1 (or one thermostat's T_ONLINE). Examples:
    • T_FILTER1_CHANGE = 1 → send a notification.
    • SENSOR1_MOTION = 1 → a room is in use.
    • T_STATE = Heating / Cooling → show an icon on a custom screen.
  • Custom actions (Workflows > Custom): SetMode, SetHeatSetpoint, SetCoolSetpoint, SetRange, ClearSavedSetpoints, ResetFilter1, ResetFilter2, RefreshThermostat (each with a Thermostat argument: 1, 2, 3 ..., blank = 1), RefreshAllThermostats, RequestAllStates.

Every state is listed in Appendix A.

Logs: journalctl -u t10link-bridge on Linux; ~/T10Link/logs/bridge.log on a Mac.

Uninstall: sudo /opt/t10link/uninstall.sh (Linux) or sudo t10link uninstall (Mac). Add --keep-config to save the settings and pairing first; reinstalling on a Mac restores them automatically. The thermostat keeps the bridge's HomeKit pairing, so keep that backup, or unpair the thermostats on the web page before uninstalling if you won't be back.

Commands the bridge accepts on port 2400: SETMODE OFF|HEAT|COOL|AUTO, SETHEAT <t>, SETCOOL <t>, SETTEMP <t> (active setpoint), SETRANGE <heat>,<cool>, INCHEAT, DECHEAT, INCCOOL, DECCOOL, RESETFILTER <1|2>, CLEARSAVED (forget saved setpoints), DUMP, REFRESH, PING. Put @N in front for thermostat N (@2 SETHEAT 70); without it a command goes to thermostat 1 (REFRESH to all). The profile sends the same with colons, @2:SETHEAT:70.

How it works

  • HomeKit on the T10 is an encrypted HTTP connection to the thermostat on port 80. The bridge pairs once (SRP with the setup code), then opens an encrypted session with the saved keys and subscribes to push events. A safety poll runs every minute.
  • The thermostat's Wi-Fi sleeps aggressively, and its multicast (Bonjour) announcements don't reliably reach the LAN. So the bridge never relies on discovery: it connects by IP and asks the thermostat directly (unicast mDNS) for its HomeKit record when pairing.
  • HomeKit works in Celsius. When a Celsius setpoint is written, the T10 converts it to °F and rounds up. So for a whole °F the bridge writes the Celsius value that rounds up to exactly that °F (73 °F = 22.5 °C; 23.0 °C would become 74 °F).
  • In Heat/Cool mode the thermostat's real setpoint is HomeKit's target temperature. Its heating/cooling thresholds hold the Auto values, and writes to them are reverted outside Auto. The bridge confirms a change only when the value still holds on a read two seconds later, because a rejected write is echoed once before the thermostat reverts it.

Every state the bridge sends. Temperatures are in the thermostat's display units (T_UNITS).

These are thermostat 1's names. With several thermostats, thermostat n's states are the same with T_ replaced by Tn_ (T2_MODE), SENSOR prefixed with Tn_ (T2_SENSOR1_TEMP) and _1 replaced by _n (ThermostatMode_2). The SYS_ states cover the whole bridge.
